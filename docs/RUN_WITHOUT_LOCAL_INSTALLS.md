# Running PETCO Without Installing Tools on Your Laptop

If you do not want to install Node.js, Flutter SDK, Android Studio, Firebase CLI, and gigabytes of dependencies on your laptop, you can run and test PETCO entirely in the cloud using **4 zero-install methods**.

---

## Method 1: GitHub Codespaces (Recommended — 100% in Browser)

GitHub gives **60 free hours per month** of high-performance cloud virtual machines with pre-configured developer environments.

### Steps:
1. Push your PETCO folder to a GitHub repository:
   ```bash
   git init
   git add .
   git commit -m "Initial PETCO Commit"
   git remote add origin https://github.com/YOUR_USERNAME/PETCO.git
   git push -u origin main
   ```
2. Open your repository on **[github.com](https://github.com)**.
3. Click the green **`<> Code`** button $\to$ Select the **`Codespaces`** tab $\to$ Click **`Create codespace on main`**.
4. A full VS Code editor will open inside your web browser (Chrome, Edge, Safari).
   - Our included [`.devcontainer/devcontainer.json`](file:///c:/Users/shaik/OneDrive/Desktop/PETCO/.devcontainer/devcontainer.json) will automatically install Node 20, TypeScript, Flutter, and run `npm install`.
5. In the Codespaces terminal at the bottom:
   ```bash
   # Run Backend API
   npm run dev:backend

   # Run Provider Web Portal
   npm run dev:provider

   # Run Admin Console
   npm run dev:admin
   ```
6. **Instant Browser Previews**: Codespaces will automatically detect Ports `3000`, `3001`, and `4000` and give you public clickable URLs to interact with the live apps right in your browser!

## Method 2: 1-Click Free Cloud Deployments (Permanent Live URLs)

You can connect your GitHub repository directly to free cloud platforms that build and host everything for you without your laptop doing any work.

### 1. Backend API on Railway or Render
- Sign in to **[Railway.app](https://railway.app)** or **[Render.com](https://render.com)** with your GitHub account.
- Click **"New Project"** $\to$ **"Deploy from GitHub repo"** $\to$ Select your `PETCO` repository.
- Root directory: `backend`
- Build command: `npm install && npm run build --workspace=@petco/shared && npm run build`
- Start command: `node dist/server.js`
- Railway/Render gives you a permanent live HTTPS link (e.g. `https://petco-api.up.railway.app`).

### 2. Provider Web & Admin Web on Vercel
- Sign in to **[Vercel.com](https://vercel.com)** with GitHub.
- Click **"Add New Project"** $\to$ Import your `PETCO` repo.
- For Provider Portal:
  - Root directory: `apps/provider-web`
  - Framework: Next.js (automatically detected)
  - Environment variable: `NEXT_PUBLIC_API_URL = https://your-railway-backend.up.railway.app/api/v1`
  - Click **Deploy** $\to$ Instant live URL: `https://petco-provider.vercel.app`.
- Repeat for `apps/admin-web` $\to$ Instant live URL: `https://petco-admin.vercel.app`.

## Method 3: Testing the Flutter Mobile App (Without Android Studio)

You don't need Android Studio or the Flutter SDK on your laptop to compile and test the mobile application:

### A. Automatic Cloud APK Builds via GitHub Actions
We already created [`.github/workflows/ci.yml`](file:///c:/Users/shaik/OneDrive/Desktop/PETCO/.github/workflows/ci.yml). Whenever you push code:
1. GitHub's cloud servers compile your Flutter app into an `.apk` file.
2. Go to the **Actions** tab on your GitHub repo.
3. Click on the latest workflow run $\to$ Scroll to **Artifacts** $\to$ Download `app-release.apk`.
4. Transfer the file to any Android phone or test device and install it directly!

### B. In-Browser Phone Simulator (Appetize.io)
If you do not have an Android device:
1. Go to **[Appetize.io](https://appetize.io)** (free tier).
2. Upload the `app-release.apk` generated by GitHub Actions.
3. You get an interactive virtual Android phone running directly in your web browser where you can tap, scroll, and test the PETCO customer app!

## Method 4: Docker Desktop (If you already have Docker)

If you have Docker Desktop installed on your laptop, you do **not** need to install Node, Flutter, or database tools. A single command spins up isolated containers for all services:

```bash
docker-compose up --build
```

- **Fastify API**: `http://localhost:4000` (Swagger docs at `/docs`)
- **Provider Portal**: `http://localhost:3000`
- **Admin Center**: `http://localhost:3001`
- **In-Clinic TV Queue**: `http://localhost:3000/queue/loc-banjara-hills-01`
